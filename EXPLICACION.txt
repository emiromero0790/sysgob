SYSJOBS - QUE HACE CADA COSA
============================

El codigo no lleva comentarios; este archivo los sustituye.
El flujo completo es:

  acopio -> procesar -> analizar -> indexar -> evaluar -> web
  (JSON)   (CSV/SQLite/JSONL/Mongo) (estadisticas + texto) (BM25 + TF-IDF + embeddings) (metricas) (interfaz)

Coincide con las cuatro capas del PDF: adquisicion, procesamiento,
indexacion/busqueda y presentacion.


------------------------------------------------------------------
1. ARCHIVOS DE LA RAIZ
------------------------------------------------------------------

main.py
  Punto de entrada. Define los comandos de terminal con argparse:
  acopio, demo, procesar, analizar, indexar, evaluar, exportar, construir
  (procesar+analizar+indexar+evaluar), todo (acopio+construir), buscar y web.
  Cada funcion paso_* importa el modulo que necesita y lo ejecuta.
  Si falta un paso anterior (FileNotFoundError) muestra que comando correr.
  "exportar" regenera CSV, JSON, JSONL, SQLite y documentos MongoDB a partir
  de las ofertas ya guardadas, sin repetir el acopio ni la indexacion.

config.py
  Todas las constantes en un solo lugar:
  - Rutas de data/ (crudo, procesado, indices, analisis, evaluacion y
    no_relacional), incluidas las de JSON, JSONL, CSV auxiliares, matriz
    TF-IDF, vocabulario y estructura de la vectorizacion.
  - AGENTE: el User-Agent con el que se identifica el recolector.
  - PAUSA, TIEMPO_ESPERA, REINTENTOS, LIMITE_POR_FUENTE: cortesia y limites
    del acopio.
  - FUENTES_POR_DEFECTO: fuentes que usa "python main.py acopio".
  - GETONBOARD_PALABRAS, REMOTIVE_CATEGORIAS, PALABRAS_TI: que categorias
    u ofertas se consideran de sistemas/TI en cada fuente.
  - SITIOS_HTML: lista de sitios que se raspan con BeautifulSoup. Cada uno
    tiene paginas de listado, el patron de los enlaces a ofertas y selectores
    CSS de respaldo. Para agregar otro portal basta anadir otro diccionario.
  - UMBRAL_CASI_DUPLICADO: similitud coseno a partir de la cual dos ofertas
    se consideran la misma (0.9).
  - ESTRATEGIA_TOKENS: "lema", "derivada" o "palabra"; decide que forma se
    indexa. QUITAR_NUMEROS, MIN_LONGITUD_TOKEN, NGRAMAS, TOP_TERMINOS y
    TOP_NGRAMAS controlan la limpieza y las estadisticas de texto.
  - FORMATOS_EXPORTACION, MONGO_URI, MONGO_BD y MONGO_COLECCION: salidas
    relacionales y documentales.
  - BM25_K1, BM25_B: parametros del ranking lexico.
  - BACKEND_EMBEDDINGS: "auto", "sbert" o "lsa". MODELO_EMBEDDINGS: modelo de
    Sentence-Transformers. DIM_LSA: dimensiones del respaldo.
  - PESO_SEMANTICO: peso de la senal semantica en el ranking hibrido (0.6).
  - RESULTADOS_POR_PAGINA: k por defecto de la interfaz.
  - CORTE_EVALUACION: k de las metricas (10).

requirements.txt / requirements-minimo.txt
  Librerias. La minima omite sentence-transformers y faiss-cpu.


------------------------------------------------------------------
2. acopio/  (CAPA 1: ADQUISICION)
------------------------------------------------------------------

base.py
  fecha_iso(valor)   convierte timestamps o fechas a "AAAA-MM-DD".
  class Recolector   clase madre de todas las fuentes:
    __init__      crea la sesion HTTP con el User-Agent y carga los ids ya
                  guardados para no repetirlos.
    permitido     si la fuente respeta robots.txt, lo descarga una vez por
                  dominio y pregunta si la URL esta permitida.
    obtener       hace el GET con pausa, tiempo de espera y reintentos con
                  espera creciente ante errores 429/5xx. Devuelve None si falla.
    registro      arma el registro crudo con un esquema comun para todas las
                  fuentes: id (fuente + hash de la URL), fuente, url, titulo,
                  empresa, descripcion_html, ubicacion, modalidad_origen,
                  nivel_origen, etiquetas, fecha_publicacion, fecha_extraccion.
    guardar       escribe un JSON por oferta en data/crudo/<fuente>/<fecha>/.
    recolectar    generador que cada fuente sobreescribe.
    ejecutar      recorre recolectar, descarta ofertas sin titulo o sin texto,
                  guarda, respeta el limite y anade un renglon a
                  data/crudo/bitacora.jsonl (nuevas, repetidas, peticiones,
                  errores, bloqueos por robots, segundos).

getonboard.py   API publica de Get on Board (empleo tech en Latinoamerica,
                ofertas en espanol; es la fuente mas cercana al perfil).
  categorias    pide la lista de categorias y se queda con las de sistemas.
  convertir     traduce una oferta de la API al esquema comun (une descripcion,
                funciones, deseables y beneficios; mapea modalidad y seniority).
  recolectar    pagina cada categoria repartiendo el limite entre ellas.

remotive.py     API publica de Remotive (empleo remoto). Una sola peticion;
                filtra por categoria de software, devops, datos y QA.

arbeitnow.py    API publica de Arbeitnow. Pagina resultados y conserva solo
                ofertas cuyo titulo o etiquetas contienen palabras de TI.

sitio_html.py   Raspador generico de portales HTML (configurado para
                Computrabajo en config.SITIOS_HTML). Si respeta robots.txt.
  buscar_json_ld  busca en la pagina el bloque schema.org "JobPosting" que los
                  portales publican para Google.
  texto_de, lugar_de  sacan empresa y ciudad de ese bloque.
  enlaces       recorre las paginas de listado y junta los enlaces a ofertas.
  extraer       usa el JobPosting si existe; si no, cae a <h1> y a los
                selectores CSS configurados.
  recolectar    visita cada oferta; si hay 5 fallos seguidos abandona el sitio.

manual.py       Lee los CSV de data/manual (plantilla.csv trae los
                encabezados) para integrar ofertas capturadas a mano.

demo.py         Genera ofertas sinteticas combinando puestos, niveles y
                modalidades. Solo sirve para probar sin internet. Todas dicen
                en su texto que no son vacantes reales.

ejecutar.py
  catalogo      diccionario nombre -> recolector (incluye los SITIOS_HTML).
  acopiar       corre las fuentes pedidas e imprime el resumen de cada una.


------------------------------------------------------------------
3. procesamiento/  (CAPA 2: PROCESAMIENTO Y ANALISIS)
------------------------------------------------------------------

limpieza.py
  STOP_ES, STOP_EN, STOP_DE, STOP_FR y STOPWORDS: palabras vacias de los
                cuatro idiomas presentes en el corpus.
  html_a_texto  quita etiquetas, scripts y estilos; conserva saltos de linea y
                vinetas; si el HTML venia escapado hace una segunda pasada.
  limpiar_texto quita URLs, correos, emojis, numeros opcionales, signos no
                permitidos y normaliza espacios. Conserva c++, c#, node.js,
                .net y rutas como ci/cd.
  normalizar    minusculas, Unicode NFC/NFD y sin acentos.
  raiz          derivacion ligera de respaldo (compatibilidad).
  palabras      separa en tokens conservando terminos tecnicos.
  tokenizar     palabras - stopwords + estrategia (lema, derivada o palabra).
                Lo usan el indice lexico, TF-IDF, duplicados y LSA.
  tokenizar_detalle  devuelve cada palabra con su lema, raiz, si es tecnica
                y si se elimino por ser palabra vacia. Alimenta la vista Texto.
  quitar_vacias, ngramas  utilidades usadas por las estadisticas.
  idioma        "es", "en", "de", "fr" o "desconocido" segun las stopwords
                que predominan en el texto.

lematizador.py
  Reglas propias para espanol e ingles, sin NLTK ni spaCy.
  TECNICOS      terminos que no deben deformarse (python, javascript, react...).
  IRREGULARES   formas verbales y plurales irregulares.
  _plural_es/_plural_en, _genero_es, _verbal_es/_verbal_en y sufijos de
                derivacion reducen variantes a una forma comun.
  lematizar     palabra -> lema legible (p. ej. "desarrolladores" ->
                "desarrollador").
  derivar       lema -> raiz mas agresiva (p. ej. "desarrollo" -> "desarroll").
  analizar_palabra  devuelve palabra, lema, derivada y si es tecnica.
  ejemplos_lematizacion  selecciona casos reales para mostrar en la interfaz.

estadisticas_texto.py
  analizar_texto  recorre el corpus y calcula frecuencias de lemas y raices,
                  frecuencia documental, hapax, diversidad lexica, n-gramas
                  (2 y 3), palabras vacias, nube de palabras y una muestra
                  del antes/despues de varias ofertas.
  analizar_y_guardar  escribe data/analisis/texto.json. Alimenta la vista
                  Texto y los resumenes que se pueden escuchar.

entidades.py    Diccionario controlado + expresiones regulares.
  TECNOLOGIAS   75 tecnologias con sus alias.
  compilar      crea un regex con limites de palabra que entienden simbolos
                (para que "java" no coincida dentro de "javascript").
  tecnologias   lista de tecnologias mencionadas en un texto.
  modalidad     remoto / hibrido / presencial / no especificada. Prioridad:
                campo de la fuente, titulo, descripcion.
  nivel         practicante / junior / semi-senior / senior / no especificado.
                Prioridad: titulo, campo de la fuente, descripcion, anos de
                experiencia pedidos.
  area          backend, frontend, fullstack, movil, datos, devops, qa,
                seguridad, soporte, desarrollo general u otra, segun el titulo
                y, si no alcanza, las tecnologias.

duplicados.py
  quitar_exactos          hash de titulo + empresa + inicio de la descripcion.
  quitar_casi_duplicados  TF-IDF y similitud coseno; de cada par que supere
                          el umbral conserva la primera que leyo (la misma
                          vacante publicada en dos portales).

almacen.py
  ESQUEMA_RELACIONAL  define cinco tablas: fuentes, empresas, tecnologias,
                ofertas y oferta_tecnologia (relacion N:M con posicion).
  guardar       escribe data/procesado/ofertas.csv y reconstruye
                data/procesado/sysjobs.db con claves foraneas, indices y la
                vista vista_ofertas (oferta + fuente + empresa + tecnologias).
  cargar        lee todas las ofertas desde la vista normalizada y arma la
                lista de tecnologias. Conserva compatibilidad con bases viejas.
  ids_filtrados traduce los filtros de la interfaz (modalidad, nivel, fuente,
                area, idioma y tecnologias) a un WHERE de SQL y devuelve los
                ids permitidos.
  conteos       cuenta filas por tabla para la vista Datos.

exportar.py
  documento     arma el documento anidado para una base no relacional:
                empresa, clasificacion, tecnologias, fechas y metadatos.
  exportar      escribe ofertas.json, ofertas.jsonl, los CSV auxiliares
                (tecnologias, empresas, fuentes y relacion N:M) y las
                colecciones de data/no_relacional.
  exportar_todo recarga el corpus desde SQLite, lo vuelve a guardar y regenera
                todos los formatos. Es lo que ejecuta "python main.py exportar"
                y el boton "Regenerar exportaciones" de la interfaz.

pipeline.py
  leer_crudos   lee todos los JSON crudos (ignora "demo" si hay datos reales).
  transformar   crudo -> registro normalizado con entidades e idioma.
  procesar      orquesta limpieza, entidades, duplicados, guardado y
                exportacion; escribe resumen.json con el embudo (crudas, sin
                texto, duplicados exactos, casi duplicados, finales).

analisis.py
  analizar      calcula y guarda data/analisis/estadisticas.json: totales,
                conteos por fuente, modalidad, nivel, area, idioma y mes,
                tecnologias mas pedidas, longitud media, tamano del
                vocabulario y terminos mas frecuentes. Ademas llama a
                estadisticas_texto para generar data/analisis/texto.json.


------------------------------------------------------------------
4. indexacion/  y  busqueda/  (CAPA 3: INDICES Y RANKING)
------------------------------------------------------------------

indexacion/lexico.py   class IndiceLexico
  construir   indice invertido: termino -> lista de [documento, frecuencia],
              longitudes de documento e IDF.
  guardar / cargar   lo persiste en data/indices/lexico.json.gz.
  buscar      puntua con BM25 y devuelve (id, puntaje) ordenado.

indexacion/semantico.py
  elegir_backend   "sbert" si sentence-transformers esta instalado, si no "lsa".
  cargar_faiss     importa FAISS si existe.
  class Codificador   convierte texto en vectores normalizados.
    sbert: modelo multilingue de Sentence-Transformers (384 dimensiones).
    lsa:   TF-IDF + SVD truncada; el modelo ajustado se guarda en lsa.joblib.
  class IndiceSemantico
    construir   genera los embeddings de todas las ofertas y, si hay FAISS,
                crea un IndexFlatIP (producto interno = coseno).
    guardar     vectores.npy, vectorial.faiss (si aplica) y meta.json.
    cargar      los lee de disco y prepara el codificador.
    buscar      codifica la consulta y devuelve (id, similitud) ordenado.

indexacion/vectorizacion.py
  texto_lexico      titulo (dos veces) + empresa + tecnologias + descripcion,
                    el mismo texto que usa el indice lexico.
  construir_estructura  ajusta un TfidfVectorizer con el tokenizador propio
                    (sublinear_tf, norma L2) y guarda:
                      matriz_tfidf.npz      matriz CSR documentos x terminos
                      vocabulario.json.gz   termino, indice, df e idf
                      estructura.json       resumen, vector de ejemplo y
                                            postings de un termino
                    Tambien lee los embeddings ya guardados para mostrar sus
                    dimensiones, norma y primeros valores.
  _vector_ejemplo   extrae los componentes con mayor peso de la primera oferta.
  _postings_ejemplo lee el indice invertido y muestra documentos, frecuencia
                    e IDF de un termino (por defecto "python").

indexacion/construir.py
  texto_lexico     titulo (dos veces, para darle peso) + empresa + tecnologias
                   + descripcion.
  texto_semantico  titulo, nivel, modalidad, tecnologias y descripcion, en ese
                   orden porque el modelo solo lee los primeros 256 tokens.
  indexar          construye y guarda el indice lexico, el semantico y la
                   estructura TF-IDF, e imprime sus tamanos.

busqueda/motor.py   class Motor
  __init__   carga ofertas e indices y verifica que correspondan.
  senales    puntaje lexico normalizado al mejor resultado (0 a 1) y similitud
             coseno (0 a 1) para cada oferta.
  ranking    lexico, semantico o hibrido. Hibrido = 0.6 x semantico +
             0.4 x lexico (PESO_SEMANTICO).
  resumen    fragmento de la descripcion cercano a un termino de la consulta.
  tarjeta    datos que la interfaz muestra de cada resultado.
  buscar     aplica filtros (SQL, incluido idioma) y devuelve los primeros k.
             Sin consulta devuelve las ofertas mas recientes.
  comparar   primeros 8 de lexico y de semantico, marcando los exclusivos.
  detalle    oferta completa por id.

5. evaluacion/
------------------------------------------------------------------

consultas.json  14 consultas de prueba, redactadas a proposito con sinonimos,
                cada una con los criterios que debe cumplir una oferta para
                contarse como relevante (area, nivel, modalidad, tecnologias).
                Se evaluan las que tienen al menos un documento relevante
                (13 en la corrida incluida).
metricas.py     precision_k, recall_k, precision_promedio (AP) y ndcg_k.
evaluar.py
  cumple        decide si una oferta satisface los criterios.
  evaluar       corre cada consulta en los tres modos, promedia y guarda
                data/evaluacion/resultados.json.

7. DECISIONES Y DIFERENCIAS RESPECTO AL PDF  (leer antes de exponer)
------------------------------------------------------------------

a) Fuentes. El PDF mencionaba OCC, Computrabajo, LinkedIn y la bolsa del ITM.
   - LinkedIn no tiene API publica de vacantes y sus terminos prohiben el
     raspado; OCC carga las ofertas con JavaScript. No se automatizaron.
   - Se usan tres API publicas y documentadas (Get on Board, Remotive,
     Arbeitnow) mas el raspador HTML de Computrabajo. Con eso se cumple
     "al menos tres fuentes" de forma automatizada.
   - La bolsa del ITM y LinkedIn entran por data/manual (CSV), que es la
     "exportacion manual" que ya contemplaba el PDF.
   - Remotive pide en sus condiciones citar la fuente y enlazar a la oferta
     original: la interfaz muestra la fuente y el enlace en cada oferta.

b) Whoosh/Elasticsearch -> indice invertido propio con BM25. Whoosh ya no
   tiene mantenimiento y da problemas en Python reciente. El indice propio
   se guarda en disco y deja ver exactamente como funciona BM25.

c) Lematizacion y derivacion -> reglas propias para espanol e ingles, para no
   depender de spaCy ni NLTK. El lematizador usa diccionarios de formas
   irregulares y reglas de plural, genero, conjugacion y sufijos; el derivador
   produce una raiz mas agresiva. Los terminos tecnicos se protegen para que
   "python" o "javascript" no se deformen. No es tan preciso como un modelo
   entrenado, pero es explicable, reproducible y no agrega 500 MB de modelos.

d) Parquet -> CSV + SQLite + JSON/JSONL + MongoDB. Parquet exigia pyarrow sin
   aportar nada al tamano de este corpus. Las cuatro representaciones cubren
   hoja de calculo, API, carga masiva, consultas relacionales y documentos.

e) Respaldo LSA. Si sentence-transformers o FAISS no estan instalados el
   sistema no falla: usa LSA y NumPy. En "Corpus e indices" siempre se ve
   que modelo y que motor vectorial se usaron realmente.

f) Corpus bilingue. Remotive y Arbeitnow publican en ingles (Arbeitnow
   tambien en aleman). El modelo de embeddings es multilingue, asi que una
   consulta en espanol recupera ofertas en ingles; el indice lexico no puede.
   Es un buen caso para el analisis critico lexico vs semantico.

g) Evaluacion con juicios automaticos. No hay juicios de relevancia hechos
   por personas: una oferta es "relevante" si sus campos extraidos cumplen
   los criterios de consultas.json. Esos campos se extraen con palabras
   clave, lo que favorece un poco al enfoque lexico. Las metricas sirven
   para comparar estrategias entre si, no como medida absoluta. Si el
   profesor pide mas rigor, lo correcto es etiquetar a mano los primeros
   resultados de algunas consultas.

h) El "% de relevancia" es el puntaje del ranking, no una probabilidad. En
   modo lexico es relativo al mejor resultado (el primero siempre marca 100).

i) La matriz TF-IDF se guarda aparte del indice semantico. El PDF pedia
   "vectorizar" y mostrar las estructuras; por eso matriz_tfidf.npz conserva
   la matriz CSR real (documentos x terminos) y estructura.json resume sus
   dimensiones, densidad, vocabulario, IDF y un vector de ejemplo. El motor
   de busqueda puede usar embeddings, pero la explicacion de la vectorizacion
   clasica queda visible y verificable.

j) La voz se resuelve en el navegador con la Web Speech API. No se instala
   nada en el servidor ni se sube audio: SpeechRecognition convierte la voz en
   texto y speechSynthesis lee los resultados. La desventaja es que depende del
   navegador (Chrome/Edge funcionan mejor) y de las voces del sistema.

k) La interfaz se reescribio como un panel con cinco vistas y un sistema de
   diseno propio (variables CSS, tema claro/oscuro, tarjetas de vidrio,
   graficas y drawer de filtros). Se priorizo que cada concepto del PDF
   (preprocesamiento, n-gramas, vectorizacion, formatos, evaluacion) se pueda
   explicar desde la pantalla, no solo desde la terminal.

l) El modelo no relacional se entrega como JSONL y colecciones JSON, no como
   una instancia de MongoDB. Asi el proyecto funciona sin servidor de base de
   datos y, si se necesita, importar_mongo.py carga todo con pymongo.
